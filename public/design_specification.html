Architecture & Design Specification

Are You a Prompting Wizard?

A real-time, multi-player AI prompt recreation web game for live demo environments.

1. System Architecture & Overview

"Are You a Prompting Wizard?" is a dual-screen party web application designed for interactive live event booths and presentation stages. The game challenges players to recreate target images using text prompts on their smartphones.

  • Single Vanilla Big Screen (Public Display): Runs on a large TV/projector. Driven by a non-playing Event Host. Eliminates split-screen clutter for a clean, unified view featuring prominent centerpiece QR codes, target benchmark images, public timers, voting grids, and winner celebrations.
  • Mobile Controller (Instant Player Check-In): Touch-optimized mobile web UI accessed via QR code scan. Eliminates text input for wizard names; players tap to join and are automatically assigned numbers (Wizard #1, Wizard #2, etc.) in join sequence.
  • Google Brand Design System: Interfaces are styled using Google's official brand palette (Google Blue #4285F4, Red #EA4335, Yellow #FBBC04, Green #34A853) over dark material surfaces (#171717 / #202124).
  • Automatic 2K Image Optimization Engine: Startup routines automatically scan target image assets. Any image exceeding 5 MB is automatically resized to 2K high-resolution (max 2048px bounds, ~1.6MB each), improving load speeds by ~93% on mobile cellular & Wi-Fi networks.

2. Game State Machine & Phase Lifecycle

The game follows a strict, state-driven lifecycle designed to maintain high energy and prevent stalls during live audience demonstrations.

1. LOBBY Untimed
2. PROMPTING 60 Seconds
3. GENERATING Max 10 Seconds
4. VOTING 30 Seconds
5. RESULTS Host Controlled
6. RESET New Session

Phase Breakdown

  1. Lobby Phase: Displays centerpiece prominent QR Code on the left side-by-side with a random gallery preview image on the right. Tracks connected players (Wizard #1, Wizard #2, etc.). Enforced Rule: The start screen showcase image is strictly for gallery preview and is never used as the actual target image during play.
  2. Prompting Phase (60s): Main Screen shows actual game target image (selected from collection excluding start preview) and countdown timer. Players type their text prompt on mobile. Minimum requirement: 2 words. Automated auto-submit triggers at 0s.
  3. Generating Phase (Parallel API Render): Backend executes all valid prompts simultaneously via procedural generative canvas engine with a hard 10-second timeout fallback.
  4. Voting Phase (30s): Main display presents target image + randomized grid of generated artwork labeled anonymously with letters (A, B, C, D, E). Mobile controllers display corresponding vote buttons.
  5. Results & Reveal Phase: Displays winning artwork (most votes), vote tallies, and full prompt & author reveals. Confetti celebration triggers.
  6. Reset Phase: Main display purges session state, resets join counters, and picks a new start preview image for the next group of spectators.

3. Host Controls & Content Moderation Edge Cases

Host Master Overrides

  • Reroll Preview Image: Allows Host to draw a new random preview image on the start screen.
  • Force Start Game: Enables Host to launch the game as soon as 1 or more players have joined.
  • Force End Prompting: Immediately locks prompt inputs and proceeds to image generation.
  • Force End Voting: Immediately tallies current votes and jumps to the Results phase.
  • New Session Reset: Resets game state and room roster at any time.

Safety Filters & Technical Fallbacks

  • Moderation Blocked Prompts: Prompts containing prohibited keywords are excluded from voting letter assignment and render as an Educational Safety Card explaining AI moderation rules.
  • Short Prompts (< 2 words): Disqualifies prompt submission. Mobile controller informs player: "Prompt too short! Minimum 2 words required."
  • 2K Image Compression Guard: Automatically downscales large target images (> 5MB) to 2K resolution on server boot.
